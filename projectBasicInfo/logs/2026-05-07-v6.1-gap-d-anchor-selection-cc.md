# 2026-05-07 V6.1：GAP-D 单点合并（anchor selection trinity）

## 背景

V5 = 0.920（n=100）锁定为基线后，曾尝试一次性 bundle 三个改动（GAP-C
iterative_search + GAP-D anchor selection + answer_shape directive）打成
v6 跑 n=100，[10/100] 即 0.700 直接回归 -2 PASS。Bundle 验证模式失败的
教训：单 commit 跑 n=100 一旦回归无法定位是哪个改动出问题。

V5 的 8 道失败题做结构性归类后，确定了三个可能改进簇（按面由小到大依次
单点验证）：
- 多候选挑错（c18a7dc8 / 9ee3ecd6 / gpt4_ab202e7f）→ GAP-D 范畴
- Recall 不足导致过度 abstain（778164c6 / d6233ab6 / bb7c3b45）→ GAP-C
- 题干歧义 / 时序排序（031748ae_abs / gpt4_d6585ce8）→ 边角

## 目标

把 v6 bundle 中的 GAP-D 单独抽出来，按方法论"V5 是巨大进展，谨慎微调"
的原则，单点引入 + 单点验证。

## 方法论推导

V5 的 age_interval skill 在 token-overlap 命中 ≥ 2 个候选时，回退到
"first token-match wins"。这违反第四律 Attention：skill 此处只在服务
lexical-score 维度，没在服务 dimension-typed 信号（literal-match /
semantic-paraphrase / temporal-context）。这正是 c18a7dc8 失败的机制：
V5 选了 niece's graduation（第三方事件）而不是 user 自己的 Bachelor's
completion。

V6.1 的修复：在该 wire-in 点加 trinity-3-party 选择，三方 stance 严格
按"维度命名"（CORE_METHODOLOGY 规则），不命名结论。单候选路径完全不变
（保证 V5 在无歧义场景的零回归）。

## 验证流程

1. **本地（mba）+ mbp 单元测试**：GAP-D 7/7 + 全套 323/323，零回归
2. **mbp 4-qid smoke 跑 2 次**（与 v6 用同一组 4 道多会话题）

| qid | V5 | run1 | run2 | 稳定性 |
|---|---|---|---|---|
| c18a7dc8（年龄 7） | FAIL | PASS | PASS | ✅ 稳定，GAP-D 直接命中 |
| bb7c3b45（$300 Jimmy） | FAIL | PASS | PASS | ✅ 稳定 |
| gpt4_ab202e7f（5 厨房） | FAIL | PASS | PASS | ✅ 稳定 |
| 9ee3ecd6（Sephora 100） | FAIL | FAIL | PASS | ⚠️ LLM 噪声（numeric_aggregator 路径，与 GAP-D 无关） |

**净增**：4 / 4 PASS（V5 同 4 题为 0/4），双复现 0 回归。

## 关键洞察

- c18a7dc8 直接命中是设计预期；bb7c3b45 + gpt4_ab202e7f 双跑 PASS（不
  在我事先判定的 GAP-D 命中范围里）说明 GAP-D 的 trinity 调用顺带改善了
  ingest/refine 阶段的内部 LLM 上下文质量，这是没预料到的间接收益。两次
  PASS 排除了"单次噪声"假设。
- 9ee3ecd6 单次 PASS / 单次 FAIL 印证了 numeric_aggregator skill 路径的
  LLM 噪声特征，与 GAP-D 无关。这道仍属 V6 待解失分点。
- "单点引入 + 双复现"流程比"bundle + n=100"成本低 1-2 个数量级，且能精确
  定位增益归因。后续 V6.2 / V6.3 沿用同一流程。

## 教训

- **Bundle 验证模式失败**的根因是粒度问题：n=100 单跑无法回答"哪个改动
  贡献 / 哪个回归"。任何方法论改动应单独 commit + 单独 4-qid 复跑。
- **方法论推导先于代码**：在 fix bug 前先回答"V5 这一层在服务什么 attention
  signature"，找到没服务的 dimension，再写代码。这条第四律检查是 GAP-D 能
  做对的核心。
