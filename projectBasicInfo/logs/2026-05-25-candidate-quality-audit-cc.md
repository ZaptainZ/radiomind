# CQ-1 Candidate-Quality Audit — Close-out

**Date**: 2026-05-25
**Author**: Claude Code
**Status**: Closed. **Audit gate FAILED.** Fix v1 (stopword
expansion + sort-by-confidence) does NOT produce a net positive
under corrected metrics. CQ-2 implementation NOT started.

---

## What Triggered This Audit

LCO Round 2 re-audit (user) showed that `c3_a9fddfe69b`
(Nate "dragons") has its gold-token candidate generated by
`evidence_candidates.py::_extract_topics` but displaced from
the injected top-5 by high-`source_count` conversational
proper-noun artifacts (`Sharing`, `Yeah`, `Joanna`, `Hey Joanna`).
The conjecture: deterministic stopword extension + sort-key
swap (`(confidence desc, source_count desc)`) would lift Nate
into top-5 without breaking stable-PASS qids — exactly the
narrow-deterministic shape the project favors.

CQ-1 was opened as a read-only audit to validate that
conjecture across all 10 flip10 qids before any code change.

## Bugs in First-Pass CQ-1 (user-flagged)

1. **`_has_answer_token_in_topk` used symmetric substring
   match**: `cand_low in t or t in cand_low`. This let
   candidate `"Do"` match answer token `"dog"` for c3_Tilly,
   inflating the simulated-fix score by +1 false-positive.
   Fixed to word-boundary match (exact / s-plural variant
   / `\b<token>\b` for multi-word candidates).
2. **"Zero collateral on stable-PASS" was asserted without
   evidence**: CQ-1 is a ranking simulation, not an e2e
   run. The render block actively asks the LLM to prefer
   candidates (`evidence_candidates.py::render_evidence_candidates`),
   so candidate reorder CAN change commits. The earlier wording
   overstepped.
3. **"noise occupancy → 0"** was definitional — only
   stopword/speaker matches counted. Remaining generic framing
   tokens (`Writing / Do / How / Last / Trying / Plus / ...`)
   were not in the stopword set, so they registered as zero
   noise but still flooded the top-5.
4. **Nate "dragon" rank 15 → 6** is a directional signal, not
   a top-5 win. Counting it as a fix outcome was premature.

## Corrected Metrics (3-way split)

- **M1 — answer-token in injected top-K** (the actual gate):
  did the gold answer-token appear at a position the LLM
  sees? Word-boundary match.
- **M2 — known junk slots in default top-K**: stopword /
  conversational-opener / other-speaker matches the v1 fix
  would deterministically remove.
- **M3 — generic framing slots in top-K**: low-confidence
  proper-noun / activity-target tokens that look like
  conversation framing (verbs/connectives like "Do", "How",
  "Last", "Trying"). NOT in any stopword set; measures the
  next layer of candidate-quality debt the v1 fix leaves
  untouched.

## Reading

- Fix v1 removes 17/50 known junk slots, but **replaces 6 of
  them with previously-hidden generic framing tokens**
  (`Writing`, `Do`, `How`, `Last`, `Plus`, `Trying`, ...).
  Removing the obvious noise unveils the next layer.
- Nate "dragon" rises rank 15 → 6 but never crosses into
  top-5 in any audited condition. Calling that a "Nate fix"
  would have been false.
- M1 gate is **1/10 → 1/10**. No qid that wasn't already
  passing the M1 gate gains it under fix v1.
- c2_Maria scores M1=`.` in both conditions even though it's
  a stable e2e PASS — confirming that for date-type qids the
  candidate injection isn't the load-bearing channel; the LLM
  picks up the date from raw retrieve. (`audit answer_tokens`
  for c2_Maria was `["august"]`; candidates carry `2023-08-04`
  which doesn't satisfy a literal `\baugust\b` match. This is
  faithful to "candidate-injection contribution" rather than
  e2e PASS.)

## Root Cause of v1's No-Op

`_PROPER_NOUN_RE` matches ANY sentence-initial capitalized
word. `_PROPER_NOUN_STOPWORDS` is a 17-item list covering
pronouns / days / months. Hundreds of common English
sentence-openers (`Writing`, `Looking`, `Going`, `Talking`,
`Wanna`, `Last`, `Plus`, `Yes`, `Here`, ...) are not
filtered. The fix v1 stopword extension catches the most-
common 10-15 of these; everything else immediately fills
the freed slots.

A deeper fix would have to attack the regex itself: only
treat a capitalized word as a proper noun when it is NOT
the first word of a sentence, OR is part of a multi-word
capitalized span. This is a meaningful surgical change to
`_extract_proper_nouns` and warrants its own audit cycle.

## Decision

**CQ-2 NOT opened.** The narrow-deterministic fix v1
hypothesis is falsified by the corrected M1 metric. A
deeper extractor reform might still pay off, but it is
no longer the same one-line fix that LCO Round 2 v0
suggested. Open as a fresh investigation (e.g.,
`CQ-extractor-reform`) only if and when it becomes the
highest-priority work; otherwise leave candidate-layer
alone.

  with 3-metric output (M1/M2/M3) per qid plus full top-15

  candidate-layer change.
- Concrete falsification of the "narrow fix is enough"
  conjecture. Spends ~5s per qid, can run on every commit
  if needed.
- Diagnostic JSON (`bench/end_to_end/cq1-candidate-quality.json`)
  preserves all candidate rankings + sub-metric counts.

## Open Question for Future Work

If a `CQ-extractor-reform` is ever opened, the audit gate
should be:

  - M1 must improve by ≥ 2 net (i.e., 1/10 → 3+/10) AND
    no per-qid M1 regression (no qid goes Y → .).
  - M3 must not increase. If a v2 fix again replaces
    M2 noise with M3 noise, it has not actually helped.

These thresholds are conservative on purpose; the cost of a
prompt-side change that doesn't move M1 is real (one more
moving piece in the answer-time stack).
