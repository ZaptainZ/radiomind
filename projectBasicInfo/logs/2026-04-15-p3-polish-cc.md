## 本轮做了什么

### 1. EVIDENCE + FALSIFIER 结构化 prompt（提交 `c0c991f`）
三体博弈所有 prompt 重写：
- 每个辩手（Guardian/Explorer/Reducer）必须以 `POSITION / EVIDENCE / ACTION / FALSIFIER` 四段回答
- 合成阶段每条 INSIGHT 必须带 `CONFIDENCE / EVIDENCE / FALSIFIER`
- Dream 的 wander prompt 同样加 EVIDENCE / FALSIFIER

数据层：
- `Habit` dataclass 新增 `evidence: str` / `falsifier: str`
- HabitStore 持久化这两个字段
- `add_habit` 在重复时把新 evidence/falsifier 合并到已有 habit（如果原先为空）
- 三个 `_parse_insights`（chat / step / dream）全部改写为 4-line INSIGHT block 解析器，容忍顺序错乱和部分缺失

核心价值：habit 从此是可验证的——每条都带「证据链 + 证伪条件」，之后可以用未来的记忆自动 re-evaluate，而不是永远漂浮的信念。

### 2. 异构 refinement 后端（提交 `c0c991f`）
除了已有的 `guardian_model / explorer_model / reducer_model`，新增：
- `guardian_backend / explorer_backend / reducer_backend`
- `ChatRefinement._speak()` 把 backend 参数透传给 `LLMRouter.generate()`

典型用法：Guardian 用本地 Ollama 省钱（一致性审查不需要强模型），Explorer 用云端强模型找新模式。

### 3. 批量 ingest（提交 `c0c991f`）
- `MemoryStore.add_many()`：单事务批量插入 memories + FTS + history，N=200 时实测 **11.5× 提速**（49.5ms → 4.3ms）
- `RadioMind.ingest_batch()`：批量 ingest 多个会话，跳过每轮的 profile/KG 刷新，适合大数据导入
- 用户手动调用 `refresh_self()` 触发聚合

没做完整 async（会放大架构面），只在最高价值的地方加 batch。

### 4. UX 打磨（提交 `c0c991f`）
- `radiomind status`：habit 行按 confirmed / candidate / archived 分解，并显示 grounded（带 evidence+falsifier）的比例
- `radiomind doctor`：新增「habit grounding rate」检查，≥ 0.6 PASS，< 0.6 WARN（可能用弱 LLM 跑 refinement 导致）
- MCP `radiomind_habits` 返回的文本里也展示 evidence / falsifier 两行

### 5. KG entity resolution（提交 `9e7e545`）
- `canonicalize(entity)`：trim/去标点 + ASCII 小写 + 去中文常见后缀（市/省/县/区/镇 + 公司/有限公司/股份有限公司）
- 新 `entity_aliases` 表 + `KnowledgeGraph.add_alias()`：注册别名后，旧 triples 的 subject/object 立即重写，图一致性是瞬时的
- `add_triple / query_entity / query_relation / timeline` 都经过 `resolve()` —— 「杭州市 / 杭州」、「阿里巴巴公司 / 阿里巴巴」自动合并为同一节点

纯字符串级，零 LLM 成本，可以一直开着。

### 6. `radiomind setup-restore`（提交 `08df4ec`）
配合 P1.4 的 setup 自动备份，提供一键回滚：
- `hooks.setup.restore_latest_backup(path)`：找同目录下最新的 `*.radiomind-bak.YYYYMMDD-HHMMSS` 拷回
- CLI `radiomind setup-restore [-p platform]`：自动识别平台，恢复对应的 settings.json / hooks.json / mcp.json

setup → 备份 → 撤销 全流程闭环。
